## AppData 迁移到 E 盘（bighat 要求 C 盘 AppData 访问跳转到 E 盘）

- 勘查：`C:\Users\Administrator\AppData` 约 29.05 GB / 216,361 文件（Local 15.87 / Roaming 10.60 / LocalLow 0.58 GB）。C: 剩 9.5 GB，E: 剩 147 GB，均 NTFS；E 是内置 SATA 机械盘（非移动盘）。`E:\AppData` 原有一个空 WeWork 目录，与三个子目录不冲突。
- 硬约束：当前会话、企业微信 WXWork 的 6 个进程（WeChatAppEx / WeMailNode / WXDrive）可执行文件就位于 `AppData\Roaming\Tencent\WXWork` 内，在线状态无法重命名原目录。切换必须离线：另一管理员账户 / WinPE / ONSTART 的 SYSTEM 计划任务。
- 用户选择「分级迁移」。采用的折中方案：AppData 根目录**留在 C 盘**，只把 Local / Roaming / LocalLow 三个子目录做成 NTFS junction 指向 `E:\AppData` 同名目录，既让访问落到 E 盘，又避免登录时配置加载经过链接。
- 交付脚本：`E:\Project\workbuddy\2026-11-16-09-50-39\migrate-appdata.ps1`。7 个阶段 Status/Copy/Switch/Verify/Rollback/Schedule/Unschedule，All 与 Big 两种模式。原目录改名为 `*.bak-<stamp>` 保留回滚，**脚本从不删除 AppData 下的任何内容**。
- 技术要点：robocopy 必须 `/XJ`（AppData\Local 有 3 个自引用兼容 junction，ACL 拒绝 Everyone 读取，fsutil 也查不到目标）；用 `/COPY:DATSO /DCOPY:DAT`，禁用 `/MIR`；PowerShell 5.1 用 `New-Item -ItemType Junction -Target` 建链接，回滚用 `[IO.Directory]::Delete(link, false)` 只删链接不删目标数据（已实测验证）。
- 踩坑修复：robocopy `/LOG+` 会缓冲到进程退出才落盘，运行中日志为 0 字节，导致 FAILED 被误判为 0。改为捕获 stdout 自行解析汇总表，并对「解析不到汇总」做 fail-closed。
- 状态：在线预复制在后台进行中（27 分钟时 Local 已写入 46,319 文件 / 10.93 GB）。**切换步骤未执行**，C 盘零改动、无 junction，需用户离线自行执行。
- 预复制最终结果（耗时 1h13m）：成功 216,531 / 216,554 文件，约 28.5 GB 落到 `E:\AppData`，E 剩 119.4 GB。Roaming 114,004/114,004、LocalLow 933/933 全成功；Local 101,594/101,617，23 个失败（53 MB）全是被锁系统文件：`UsrClass.dat`(+LOG1/LOG2)、WebCache\WebCacheV01.dat 等、TileDataLayer 数据库、UWP Packages 的 settings.dat、Chrome Sessions，以及 2 个 CodeBuddyExtension auth 文件（沙箱 Access denied）。这 23 个在 E 盘均缺失，必须靠离线最终同步补齐。
- 重点风险：`Local\Microsoft\Windows\UsrClass.dat` 是 HKCU\Software\Classes 配置单元，登录时加载；切换后必须确认它已落到 E 盘，否则配置加载异常。
- 脚本增强：Switch 阶段遇 FAILED>0 会先打印失败文件完整清单再中止，便于判断能否安全使用 `-Force`；仅当剩余失败全是可丢弃的缓存/认证文件时才可放行。
- 工具状态说明：后台任务被标记 failed 只是因为 stderr 里有沙箱 file-read 拒绝信息，脚本本身正常执行到 `Copy phase finished`。
- 11:30 已注册开机切换任务 `AppDataJunctionSwitch`（MSFT_TaskBootTrigger / SYSTEM / ServiceAccount / Highest / 2h 超时，命令**不带** -Force）。并用临时探针任务以 SYSTEM 身份实跑 `-Phase Status` 验证通过（机器账户 YANGDONG$ 可读 C:\Users\Administrator\AppData、可写 E:\AppData\_migration_logs），探针任务与脚本均已清理。
- 脚本二次改动：Schedule 生成的开机命令去掉 `-Force`（否则会绕过最终同步的 FAILED 校验，让锁住的 UsrClass.dat 混过去）；Switch 全部成功后自动注销自己的开机任务，避免每次开机重跑。
