## 技术栈切换：微信小程序 → Godot Android App

- 用户决定**弃用小程序**，改用 Godot 做安卓手机端。注：用户写的 "gobot" 是安装目录名 `E:\install\gobot`，不是笔误。
- 产品需求延续「站点坞」：管理并浏览站点、体验像 APP；上一轮明确拒绝「只把网页拆成文字」的预览。
- 引擎实测：`E:\install\gobot\Godot_v4.7.2-stable_win64.exe`，`--version` = `4.7.2.stable.official.ed1daf0bf`。PATH 里没有 godot，调用要用绝对路径；console 版为 `*_console.exe`。
- 关键判断：小程序卡死的「任意站点原样渲染」，在 Android 可通过**原生 WebView 插件**（Java/Kotlin + AAR）真正执行 JS、渲染 SPA；且不需 ICP 备案、不需合法域名白名单、不需企业主体，可用 http / 裸 IP / `:7000`。推荐路线 C：自有站点走 JSON 接口原生界面，其它站点走 WebView。
- **本机 Android 导出环境三项缺口**（导出 APK 的通用硬前提，与渲染路线无关）：`%APPDATA%\Godot\export_templates\` 为空；JDK 是 `1.7.0_80`（需 17）；`ANDROID_HOME` 未设置且常见路径无 SDK。
- 重要修正：JDK 17 + Android SDK 不是 WebView 插件的额外代价，而是 Godot 导出任何 Android APK 的必需前提，所以路线 C 相对纯 Control 并未抬高门槛。
