# 2026-11-13 工作日志

## M10：搜索独立显示、可选搜索引擎、新增谷歌引擎

**需求**：搜索独立显示，可选搜索引擎；现有这套归纳为默认引擎，另外增加谷歌引擎作为可选项。

**方案**：把「引擎」作为一等概念。`app/search/engines.py` 注册 `default`（M7 原有整套：站内三组 + 搜狗/Bing RSS/百度资讯）与 `google`（新增 Google 资讯 RSS + Google 网页搜索）。`service.py` 重写为按引擎生成独立区块：各自代取、各自缓存、各自报错，结果不混排；`/api/search` 保留 M7 顶层 `groups/external/sources/errors/total` 指向默认引擎，另增 `engines/selected/engines_param/engine_choices`。`search.html` 加引擎 chips（纯 GET 链接多选，不允许取消到 0 个），每个引擎一个 `#engine-{id}` 卡片，CSS 加 `.sch-engines/.sch-engine*`。

**配置**：`config.yaml` 的 `search` 段增 `engines: [default, google]`、`default_engine: default`、`google.{enabled,providers,hl,gl,ceid,num,timeout_seconds,prefer_proxy}`；`config.py` 增 `GoogleSearchConfig`。首次打开仍只跑默认引擎，保持 M7 体验与速度。

**Google provider**：`google_news` 用 `news.google.com/rss/search`（feedparser，标题拆来源、description 是标题重复时清空）；`google_web` 用 `www.google.com/search`，按 `<a>…<h3>` 抓结果、解包 `/url?q=`、过滤 google.com 自身链接、从常见摘要 class 取简介与日期。`search_url(name,q,opts)` 向后兼容（多余 kwargs 被 format 忽略）。

**代理与等待**：实测当前会话 `proxy.url` 的 7890 端口未监听，系统沙箱代理 60781 对 google.com 返回 502，`trust_env=False` 直连超时；站点代取刻意忽略系统代理变量只认 `config.proxy.url`。为避免用户选谷歌引擎后白等 30 秒，`_external_block` 在真实运行且无缓存时先做 0.6s 端口探活，代理没开就秒回明确提示；`_remote` 对 Google 不做外层重试（内部已有 direct/proxy 两条通道），`google.timeout_seconds=8` 单独限时；有缓存时跳过预检，关代理也能看上次结果。

**踩坑**：Jinja 里 `sec.items` / `eng.items` 会取到 dict 的 `.items` 方法而不是同名 key，页面报 `TypeError: builtin_function_or_method has no len()`，改成 `sec['items']` / `eng['items']`。以后模板里给 dict 起 key 名要避开 `items/keys/values/get/copy`。

**验证**：`pytest -q` **120 passed**（新增 `tests/test_search_engines.py` 16 例）。源码服务 18081：默认页 1 个引擎区（86 条站内结果）、双引擎页 2 个独立区、`/api/search?engines=google` 与 `/api/search/status` 正确；代理不可达时 `/search?engines=google&scope=external` **0.86 秒**返回降级提示。exe 已重建（27 MB）并同步 `dist/config.yaml`、新增 `dist/config.example.yaml`（build_exe.bat 现在每次都输出最新默认配置模板且不覆盖用户配置）；exe 自检 **8/8**（自检新增搜索引擎项），exe 内双引擎页与状态接口验证通过。

**未完成/限制**：Google 真实结果未在本会话联调成功（本地代理未开启），解析与降级用 MockTransport 覆盖；用户开代理后即可用。免 key 的 Google 网页搜索为尽力而为，结构改版可能 0 条；官方 Custom Search JSON API 需 key，未接入。引擎间不做跨引擎去重（独立展示的代价）。`docs/PLAN.md` 新增第 12 章并同步目录树、配置表、页面接口表。

## M10 修正：搜索引擎选择放进搜索栏本身

**用户反馈**：「搜索栏还是没位置选引擎啊」。根因是第一版只在 `/search` 页面下方放 chips：全站顶栏搜索框没有选择入口、GET 提交不带 `engines`（换页搜索就丢选择），且 `@media (max-width:1100px)` 直接隐藏顶栏搜索框。用户说的「搜索栏」是顶栏那个框。

**做法**：`routes.py` 新增 `_engine_selection()` / `_engine_options()`，`_site()` 向所有页面注入 `engine_options`（每个单引擎 + 「全部引擎」+ 非常规当前组合）和规范化后的 `engines_param`；`base.html` 顶栏 form 与 `search.html` 主 form 内嵌 `<select name="engines" data-engine-choice>`，提交即带参数，下方 chips 保留为多选快捷并改成浅蓝卡片。`app.js` 新增 `initSearchEngineMemory()`：URL 显式带参数时以其为准并写回 `localStorage['ns_search_engines']`，否则回填上次选择，同页两个下拉联动。CSS 加 `.ts-engine` / `.sch-engine-select`，1100px 以下只缩小不隐藏顶栏搜索框，900px 以下才隐藏。配置里禁用谷歌或只剩一个引擎时两处下拉自动隐藏、改回 hidden 字段；模板用 `default([], true)` 兜住缺上下文的页面。

**验证**：`pytest -q` **130 passed**（新增 `tests/test_engine_picker.py` 10 例）。源码服务 18083：首页/行业/社媒/搜索页顶栏均含 `default / google / default,google` 三选项；模拟选 google 提交后只剩 `engine-google` 区块。exe 重建（27 MB）后自检 8/8，18084 上顶栏三选项、主框下拉、双引擎/单谷歌页面均通过。`docs/PLAN.md` 第 12 章补「搜索栏入口」小节与验收记录。

**经验**：新增「可选项」类功能时，选择控件要放在用户实际发起动作的输入控件里，而不是只在结果页做一排筛选标签；全站顶栏表单提交会重置 URL 参数，需要用表单字段 + localStorage 双保险。

## M10 布局二次修正：三段式搜索栏

**用户反馈**：「不对，搜索栏应该是 下拉框(谷歌/默认) 输入框 搜索按钮，这样的布局」。上一版虽然把下拉塞进了顶栏，但搜索页主表单是「文字 label + 下拉 + 输入框 + 按钮」四段且三个控件各自独立圆角、有 8px 间隙，看起来不像一条搜索栏；下拉还常驻第三项「全部引擎」，不是用户要的二选一。

**做法**：顶栏与 `.sch-form` 统一为 `[ 引擎下拉 ▾ ] [ 输入框 ] [ 搜索按钮 ]` 一体条（`.sch-form { gap: 0 }`，select 左圆角且 `border-right: none`、input 中段无圆角、button 右圆角；两段 select 都加 `appearance: none` + SVG 下拉箭头）。删除主表单的 `<label>搜索引擎</label>`。`routes._engine_options()` 改为只返回单引擎选项（默认/谷歌），仅当 `resolve()` 得到多引擎组合时临时补一条「全部引擎 / 当前组合」，保证组合 URL 的 selected 态不丢。下方 chips 从浅蓝卡片降级为普通一行「想同时搜多个引擎（可选）」，主入口让给搜索栏。

**验证**：`pytest -q` **130 passed**（`tests/test_engine_picker.py` 更新为断言两段下拉恰好 `[default, google]`、控件顺序 `select < input < button`、无 label、组合 URL 才出现第三项、CSS 含 `gap: 0` 与 `appearance: none`）。源码服务 18085、重建 exe 18086 均验证顶栏与主框控件顺序、两项选项、选谷歌只剩 `engine-google` 区块；exe 自检 8/8。`docs/PLAN.md` 第 12 章已同步。

**经验**：用户描述 UI 时给出的控件序列要逐字照做，别自作主张加第三项或额外的文字标签；「多选能力」可以降级为次要开关，但不能占用主搜索栏的视觉位置。

## 三次「没有下拉框」的真正根因：8000 端口是旧进程

**排查**：用户第三次反馈「还是没有下拉框」，但每轮改完在临时端口验证都有 select。查 `Get-NetTCPConnection` 发现 8000 由 **2026-11-12 17:11:30 启动、从未重启的 uvicorn 进程**占用（`python -m uvicorn app.main:app --port 8000`，PID 2240/43104，是早期 run_in_background 留下的开发服务，跨会话存活）。直接请求 `http://127.0.0.1:8000/` 实测 `<select>` 数 = 0，搜索页也是 0 —— 旧进程的 `routes._site()` 是启动时加载的旧模块，没有 `engine_options`，模板 `default([], true)` 兜底成空列表，所以条件分支永远不渲染。此前每轮都在 18083/18084/18085/18086 另起临时端口自测，**从没验证用户实际访问的 8000**。

**修复**：`Stop-Process` 停掉 2240/43104，释放 8000；用 `python -m app.server --no-browser` 在 8000 重启（读 config.yaml，沿用项目根 `data/news.db`，用户已有数据不丢）。防呆三件套：`app/main.py` 加 HTML `Cache-Control: no-store` 中间件、`routes._site()` 注入 `asset_v`（静态文件 mtime）与 `build_tag`（页脚显示「页面构建 MM-DD HH:MM」，旧进程会显示「未知（服务未重启）」）、`base.html` 给 CSS/JS 加 `?v=`；CSS 让 900px 以下顶栏换行而不再隐藏 `.topsearch`。`pytest -q` **131 passed**，exe 重建并验证。

**教训（重要）**：本地 Web 项目改完功能，必须**验证用户实际访问的那个端口/进程**，并确认它是重启后的新进程；只在新端口自测会得出「代码没问题」的假结论。用户报「改了没生效」时，先查端口占用与进程启动时间，再怀疑代码。另外旧进程常来自早期 run_in_background 任务，交付时要显式停掉或提醒重启。

## 谷歌引擎重做：从「几乎没有结果」到 40 条

**用户反馈**：「使用谷歌引擎时不能直接返回谷歌的搜索结果吗，现在几乎没有结果」。

**实测定位（三重原因）**：
1. `google_web`（`www.google.com/search`）自 2025 年起强制 JS——服务端代取只拿到约 94KB 脚本空壳，`<h3>` 数为 0；试过 Chrome/移动端 UA、`gbv=1`、`udm=14`、Cookie `CONSENT=YES+`、`hl/gl` 各种组合，全部 0 条，还频繁 429。属死源。
2. **空结果被写进缓存**：`search_cache` 里有 `google_web|AI → []`，TTL 30 分钟；代理后来开了也一直吃空缓存。
3. `scope=local`（仅站内）时谷歌引擎被代码直接掐断，不联网。
4. 唯一能出结果的 `google_news` 复用 `max_results: 12`，两源压成 12 条。

**改法**：
- `providers.py`：新增 `google_global`（同一条 RSS，`hl=en-US&gl=US&ceid=US:en`，与本地版内容基本不重合），`GOOGLE_PROVIDERS = (google_news, google_global, google_web)`，`num` 参数不再用于取结果；`google_web` 保留解析函数作向后兼容但默认不启用。
- `config.py`：`GoogleSearchConfig` 增加 `results_per_provider=20`、`global_hl/global_gl/global_ceid`，`providers` 默认改 `[google_news, google_global]`。
- `service.py`：空结果**不写缓存**且空缓存视为未命中；选中谷歌引擎时忽略 `scope=local` 抑制并在区块 note 说明；区块带 `direct_urls`（Google 网页搜索 / Google 资讯直达）。
- `search.html` + `app.css`：谷歌区块顶部加「直接在 Google 中查看」按钮条；结果标题改 `target="_blank"` 由 Google 跳转到原文，旁边保留「站内阅读」小链接；新增 `.sch-direct / .sch-ext / .sch-alt` 样式。
- 清掉库里历史 `google%` 缓存。

**验证**：8000 源码服务 `q=AI 芯片&engines=google&refresh=1` → **40 条 / 2.8 秒**（google_news 20 + google_global 20，无错误）；`scope=local` 下同样 40 条并提示「该设置只作用于默认引擎」；双引擎页 default 101 条 + google 40 条各自成区。重建 exe（27 MB，12:50）自检 8/8，18089 端口实测同样 40 条 / 2.6 秒。`pytest -q` **141 passed**（新增 `tests/test_google_results.py`）。

**结论/限制**：免 key 的 Google 网页搜索已确认不可用，所以「谷歌引擎」返回的是 Google 资讯（本地+全球），网页级搜索通过区块顶部直达按钮交给浏览器；资讯链接是 `news.google.com` 跳转链，服务端无法解码成原站 URL，故默认浏览器打开而非站内阅读。
